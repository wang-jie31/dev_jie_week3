## 1. 文档说明与范围边界

### 1.1 文档目的
本文档定义「企业房屋室内设计网站」的产品需求，覆盖**前台官网展示系统**、**后台内容管理系统**以及二者共用的 **Express 服务接口**（原型实现，端口 3001）。本文档**以需求与规格为主，并随原型迭代同步**（v1.2 起回写原型已落地内容）。v1.1 在前一版基础上改用 `lanniao.cn` 作为参考站重新生成；v1.2 将原型实现的模块变化（后台分组、业务管理、数据看板等）同步回文档；v1.3 补充后台全列表分页条规范与接口分页参数约定（详见 §1.5 参考站分析、§8、§9.4）。

### 1.2 业务定位（已确认）
一家室内设计**企业官网**，服务专长为「**个人独居温馨小家定制**」——为独居人群的小户型住宅提供温馨、实用、有审美的一体化设计服务。

> **参考站说明**：`https://www.lanniao.cn/`（蓝鸟家具 / 河北蓝鸟家具股份有限公司）是一家 **家具制造 + 全屋定制 + 招商加盟** 的品牌企业官网（始建于 1953 年，自称"72 年国货品牌"），**并非设计服务机构**。本文档**仅借鉴其信息架构骨架与视觉范式**（红黑灰国民品牌配色、中文主+英文副的双语标签版式、首页"优势卡+网格+新闻+页脚社媒矩阵"成熟结构、招商加盟页的"编号 01/02/03 结构化展示"、联系/招商页的在线留言表单），**不沿用其"家具制造 + 招商加盟"的业务定位与产品中心范式**。

### 1.3 范围（Scope）

**In Scope（v1）**
- 前台官网：首页、案例展示（私宅/小户型/公寓改造 分类）、服务套餐（列表+详情）、新闻资讯（企业新闻/行业资讯 分类）、关于我们（品牌介绍/设计流程/设计团队/发展历程/联系我们）、招聘入口（社会招聘/校园招聘）
- 后台管理（内部系统，多角色，已实现）：概览仪表盘（KPI+环比+数据可视化看板）、内容管理（案例/套餐/新闻）、客户管理（留言处理/预约处理，含沟通记录）、业务管理（项目管理/团队/工地联系）、人力与资源（招聘/用户管理/部门管理/网站设置/登录日志）
- 服务接口（Express）：前台公开只读接口 + 后台 JWT 鉴权管理接口
- 语言：先中文；架构预留 i18n 多语言扩展
- 定价模型：**双轨价格**——参考单价（元/㎡）+ 起步总价（元），套餐另含面积区间系数（见 §5.2）

**Out of Scope（本期不做，Non-Goals 详见第 3 节）**
- 在线交易 / 支付 / 电商下单 / 在线合同签署
- C 端注册登录的个人中心 / 会员体系（内部多角色权限已实现：管理员/销售/设计/客服，见 §8.1）
- 生产化技术选型与正式部署（原型采用 Express+JSON+单文件 HTML 落地，生产架构另议）
- 真实业务数据填充（由业务方在后台录入，原型内置演示种子数据）

### 1.3.1 假设与约定
- **H1（主导航计数）**：用户要求"顶部主导航控制在 5 个"，原话列举了 6 项（含"首页"）。本文档约定：**首页作为 Logo/主页入口，不计入一级导航菜单项**；一级导航共 5 个（案例展示 / 服务套餐 / 新闻资讯 / 招聘入口 / 关于我们），其中 4 个带二级下拉。若需将"首页"计入菜单或调整一级项，请告知。
- **H2（静态内容，v1.2 起部分推翻）**：v1.1 曾约定设计团队、新闻资讯、招聘岗位等内容默认静态/可配置、不进后台 CRUD；**v1.2 起已全部纳入后台 CRUD**（设计团队=团队管理 §8.12、新闻资讯=新闻管理 §8.6、招聘岗位=招聘管理 §8.9）。仍走 `SiteConfig` 站点配置维护的仅：**品牌介绍、设计流程、发展历程、联系方式**等关于我们静态内容（§8.11 网站设置）。

### 1.5 参考站分析（lanniao.cn / 蓝鸟家具）

> 本节为改用 lanniao.cn 后的参考依据。结论：**借其骨架与视觉，补我方设计服务的功能缺口**。

**1.5.1 实测结论**
- 站点性质：河北蓝鸟家具股份有限公司官网，家具制造/品牌企业，非设计服务机构。
- 路由范式：ThinkPHP 风格（`/index/index/channel.html?id=N` 频道页 + `productView/newsView` 详情页），数据库驱动 CMS。
- 视觉语言（实测 style.css）：主品牌红 `#e9212e`（出现 217 次，核心识别色）、深炭黑文字 `#27282c`、橙色点缀 `#f36727`、中性灰阶（白/浅灰/中灰/深灰）；整体"红+黑+大量留白灰"，稳重、权威、传统国民品牌风。版式上普遍采用**中文主标题 + 英文副标（ABOUT LANNIAO / PRODUCT SERIES / JOIN US / Contact Us）的双语标签**。
- 交互：基本无前端搜索/语言切换/在线客服；核心交互为"联系我们"与"招商加盟"两处的**在线留言表单**。

**1.5.4 视觉/交互借鉴决策**

## 2. 问题与背景（Problem Statement）

### 2.1 用户问题
独居青年 / 小户型业主想把自己的一居室、开间、小两居改造成「温馨、好住、有风格」的家，但普遍面临：
- **信息分散**：设计灵感、报价、流程全靠口口相传或社媒碎片，缺乏一个可信的品牌入口。
- **决策成本高**：不知道设计公司能做什么、多少钱、流程多长，不敢轻易咨询。
- **风格不确定**：想要「温馨小家」但说不清具体风格，需要案例与套餐做决策锚点。

### 2.2 业务问题
设计公司缺乏一个**结构化获客与信任建立的官网**：案例靠微信朋友圈发、咨询靠口头传递，无法沉淀内容资产，也无法量化获客效果。

### 2.3 不解决的代价
- 获客高度依赖人际与转介绍，增长天花板明显；
- 内容资产无法复用，每次获客都要重复讲解；
- 无法量化「浏览→咨询→到店→签约」的转化漏斗。

## 3. 目标与非目标（Goals & Non-Goals）

### 3.1 目标（Goals）
1. **获客闭环**：官网能承接「浏览→咨询留言→后台跟进」的完整线索链路，留言表单提交成功率 ≥ 90%。
2. **信任建立**：通过案例详情（图文/视频/项目信息）与设计师档案，提升咨询转化率。
3. **内容可运营**：业务方无需开发介入，即可在后台自主维护案例、套餐、留言。
4. **可度量**：上线后可统计案例浏览量、留言量、来源页，支撑运营决策。
5. **可扩展**：架构预留 i18n 与多角色，避免未来扩展时推倒重来。

### 3.2 非目标（Non-Goals）
1. **不做在线交易**：本期不实现支付、合同、电商下单（原因：独居小家定制属高客单决策型服务，线上仅承接线索，成交在线下）。
2. **不做 C 端会员体系**：不实现 C 端注册/登录/收藏（内部多角色权限已在 v1.2 实现，见 §8.1；官网定位品牌展示+获客，非平台）。
3. **不做生产化部署**：原型采用 Express+JSON+单文件 HTML 落地（端口 3001），生产化技术选型、数据库迁移、HTTPS/内网部署另议（见 §12、§14）。
4. **不固化具体价格数值**：案例/套餐定价的具体金额由业务方在后台录入（原型内置演示种子数据）。
5. **不实现采购/施工全流程线上化**：本期后台管理到「项目状态+工地联系」层，材料采购、财务收款、合同签署留作后续（见 §14 Q15）。

## 5. 业务模式与服务设计

### 5.1 服务模式
以「**独居温馨小家定制**」为主线，提供从咨询到落地的轻量化全案设计服务。对外以**套餐**降低决策门槛，对内以**标准流程**保障交付。

### 5.2 轻量套餐定价模型（v1.2 改为双轨价格）
v1.1 曾约定「弱化 ㎡ 计价、按空间/风格/整屋打包价」。**原型实现后改为双轨**：既给用户「每平方参考价」降低比价难度，又给「起步总价」给确定性下限，二者并存展示（前台卡片/详情显示 `¥X/㎡ 起` + `最低 Y 元/套`）。

| 套餐类型 | 维度 | 示例（价格待业务确认） |
|---|---|---|
| 单空间改造包 | 按房间 | 客厅 / 卧室 / 厨房 / 卫生间 单项设计 |
| 整屋套餐包 | 按户型 | 一居室 / 小两居 全屋设计 |
| 风格定义包 | 按风格 | 奶油风 / 原木日式 / 极简北欧 等风格方案 |
| 阶梯附加 | 按面积区间（定价系数） | 30–45㎡ / 45–60㎡ / 60–70㎡ 阶梯系数，作用于套餐的 `price_from` |

**价格字段（前后台已落地）**
- `Case.price_per_sqm`：案例参考单价（元/㎡），自动生成 `price_note`（如「全案设计约 ¥280/㎡ 起」），前台卡片/详情展示。
- `Package.price_per_sqm`：套餐单价（元/㎡）；`Package.price_from`：套餐起步总价（元）；`Package.area_step_coefficient`：面积区间阶梯系数（作用于 `price_from`）；自动生成 `price_note`。
- 后台案例管理/套餐管理均提供价格录入与展示（§8.2/§8.3）。

> **定价数值为业务决策项**：本文档定义价格「字段结构与展示方式」，具体金额由业务方在后台配置，PRD 不固化数字（详见第 14 节待决项 Q1）。

### 5.3 设计服务流程（参考 lanniao 招商加盟"三段式编号"写法，适配小家）
建议在「服务套餐详情」页与「设计流程」页展示标准化四阶段流程，给用户确定感。展示上可借鉴 lanniao 招商加盟页"编号 01/02/03 结构化卡片"的写法（要求→条件→支持），增强可读性：
1. **需求阶段**：需求问卷 → 需求沟通 → 上门量房 → 签订设计合同
2. **设计阶段**：平面初稿 → 效果图 → 软装搭配 → 施工深化 → 预算清单
3. **落地阶段**：施工交底 → 主材陪购 → 施工验收
4. **软装阶段**：搭配清单 → 软装摆场 → 新家实拍

## 8. 后台功能需求（内部管理系统，v1.2 五大分组；v1.3 补充全列表分页条规范）

> 后台定位：公司**内部人员**使用（管理员/销售/设计/客服），**不对外开放、不单只给管理员**。侧边栏按 5 分组（概览/内容管理/客户管理/业务管理/人力与资源），分组标题可点击**折叠/展开**（localStorage 记忆，刷新保持）。安全约束：后台端口（原型 3001）不得暴露公网，应走内网/VPN/反向代理 + HTTPS。

> **通用规则 · 列表分页条（v1.3 补充，原型已落地）**：后台**所有列表页**（案例/套餐/新闻/招聘/留言/预约/项目/团队/工地/用户/部门/登录日志）统一使用同一分页条组件：
> - **有数据即显示，1 页也显示**（空数据才隐藏——分页条是显式 UI 组件，不是数据多时的偶发行为）；
> - 每页默认 **10 条**；
> - 样式：圆角胶囊（`rounded-xl`）、当前页嫩黄渐变底（`btn-yolk`）+ 墨色文字、页码常态为浅米描边 + hover 米色底、**上一页/下一页在边界处为浅米色禁用态**（`cursor-not-allowed` + `disabled`），右下角固定展示「共 N 条 · 第 X/Y 页」；
> - 翻页后回到列表顶部（`scrollTo` 平滑），筛选条件变化自动回到第 1 页；
> - 交互统一由前端单函数 `pager()`/`bindPager()` 驱动，11 个列表页共用一份实现。

### 9.4 通用约定
- **响应规范（统一采用）**：响应体统一为 `{code, message, data}`。成功 `code=0`，业务异常 `code≠0` 并附 `message`；HTTP 状态码表达结果（2xx 成功 / 4xx 客户端错误 / 5xx 服务端错误）。
- **分页参数（v1.3 补充，原型已落地）**：列表接口支持 `page` / `pageSize` 查询参数——`page` 从 1 起，`pageSize` 默认 **10**、上限 **100**；分页响应结构为 `{items, total, page, pageSize}`。**不带分页参数时返回完整数组**（兼容下拉框、编辑弹窗等一次取全量场景）。
- 字段校验失败返回 400（原型采用 400，非 422）与具体错误文案。
- 公开写接口（留言）做基础校验（姓名+手机号必填）；CORS 全开以兼容前台 file:// 直开。

## 12. 技术架构与目录约定（v1.2 原型实际）

### 12.1 技术栈（原型已落地）
- **服务端**：Node.js + Express + Multer（多图上传）+ jsonwebtoken（JWT）+ crypto（sha256 加盐）；数据持久化为 JSON 文件（`data/*.json`），端口 3001。
- **后台前端**：单文件 `public/admin.html`（Tailwind CDN + 原生 JS，无构建步骤）；数据可视化为**自包含 SVG**（无图表库依赖）；侧边栏分组可折叠。
- **前台**：单文件 `index-v7.html`（Tailwind CDN + 原生 JS + 高德地图 iframe + Noto Serif SC），经 `http://localhost:3001/site/index-v7.html` 联调。
- **演示交付**：`1/` 文件夹——前台原样 + 后台**免登录静态演示版**（由 `_build_demo.js` 生成：内嵌数据快照 + mock `window.fetch`，file:// 双击即用，改动仅会话内有效，刷新还原）。
- **生产化（另议）**：可回迁原规划 FastAPI + React，或维持 Express + 前端工程化；存储从 JSON 文件迁移 SQLite/PostgreSQL。

### 12.2 目录结构（原型实际）
```
后台管理系统/
  server.js            # Express 服务：登录鉴权/CRUD/上传/公开接口/静态服务（含 /site 白名单）
  package.json
  data/                # JSON 持久化：staff departments login-logs cases packages news careers
                       #   messages site-config projects team sites.json
  public/admin.html    # 后台单文件前端（五大分组 + 数据看板 + 侧边栏折叠）
  uploads/             # 多图上传存储
1/                     # 交付文件夹
  index-v7.html        # 前台原样（交付）
  admin.html           # 后台免登录静态演示版（交付）
  _build_demo.js       # 演示版重建脚本（数据更新后重跑）
index-v7.html          # 前台开发入口
01-室内设计prd.md      # 本文档
```

> 安全约定：前台用户经 `/site/` 仅可访问 `index*.html`（白名单中间件），禁止访问后台源码与数据目录；`/api/v1/admin/*` 全部需 JWT。
