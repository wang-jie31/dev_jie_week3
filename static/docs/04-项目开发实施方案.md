## 一、项目概述

### 1.1 业务定位

一家室内设计**企业官网**，服务专长「**个人独居温馨小家定制**」——为独居人群的小户型住宅提供温馨、实用、有审美的一体化设计服务（品牌名：栖屿设计 / QIYU DESIGN）。

| 要点 | 说明 |
|---|---|
| 业务模式 | **线索型业务**：浏览案例与套餐 → 联系/预约表单留线索 → 内部跟进 → 线下成交 |
| 核心链路 | 「内容展示 → 线索收集 → 后台跟进 → 项目管理」 |
| 目标人群 | 22–35 岁独居青年、小户型业主（一居室/开间/小两居，建面 30–70㎡） |
| 关键决策因子 | 案例真实度、套餐价格透明、设计师可信度、流程清晰 |

### 1.2 系统构成（4 个子系统）

| 子系统 | 面向 | 形态 | 用途 |
|---|---|---|---|
| 前台官网 `apps/web` | 独居用户（C 端） | Next.js 15（SSG/ISR） | 首页 / 案例 / 套餐 / 新闻 / 招聘 / 关于（含联系预约表单） |
| 后台管理 `apps/admin` | 内部员工（B 端） | Vite + React SPA | 登录（4 角色）+ 概览看板 + 5 分组 13 模块 |
| 后端 API `api` | 前后台共用 | FastAPI 模块化单体 | 公开接口 + 后台 JWT 接口，OpenAPI 统一契约 |
| 数据库 | 数据层 | PostgreSQL 16 + Alembic | 20 张表，JSONB+GIN 支撑案例多维标签筛选 |

**协作关系**：前台「读内容 + 写线索」→ 后端 → 数据库；后台「写内容 + 读写业务」→ 后端（JWT）→ 数据库；后台上架内容后，通过 **revalidate 机制**触发前台 ISR 即时刷新，保证「后台上架 → 前台可见」一致。

### 1.3 需求来源与优先级

| 需求维度 | 以哪份文档为准 |
|---|---|
| 页面效果与组件视觉 | 原型 `static/prototype/*.html` + `UIUX设计文档.md` |
| 数据库设计 | `03-数据库设计文档.md`（**优先**） |
| 接口与架构 | `02-开发技术文档.md` |
| 业务字段/状态机/权限 | `01-室内设计prd.md` v1.3 |

**冲突裁决顺序**：存储以数据库文档为准 → 业务规则以 PRD 为准 → 架构与接口以技术文档为准 → 视觉以 UIUX 为准。原型只是「页面效果参考」，不是实现规范；emoji 替换为 SVG、分页条规范两条属**强制执行项**。

## 三、技术栈与总体架构

### 3.1 技术栈总表

| 层 | 选型 | ADR | 关键点 |
|---|---|---|---|
| 前台渲染 | Next.js 15 App Router（SSG + ISR） | ADR-001 | 案例/套餐/新闻列表与详情 `generateStaticParams` + ISR；SEO metadata/sitemap/JSON-LD |
| 后台渲染 | Vite + React SPA（React Router） | ADR-012 | 无需 SEO，重交互；内网部署 |
| 后端 | FastAPI 模块化单体 | ADR-003 | 5/6 限界上下文 package；router → service → repository 单向依赖 |
| 数据库 | PostgreSQL 16 | ADR-002 | JSONB + GIN 标签筛选、并发写、成熟备份 |
| 仓库 | pnpm workspace 单仓 | ADR-004 | apps/web + apps/admin + packages/ui + packages/api-types + api |
| 鉴权 | JWT access 2h + refresh 8h（落库可撤销） | ADR-005 | refresh_tokens 表；登出/改密即吊销 |
| 密码 | argon2id（旧 sha256 惰性迁移） | ADR-006 | 登录命中旧哈希时自动重写 |
| 文件 | 本地卷 + StorageBackend 抽象 | ADR-007 | put/get/delete；预留 OSS |
| 标签 | JSONB 数组 + GIN 索引 | ADR-008 | style_tags / house_type_tags |
| 敏感信息 | 应用层 AES-256-GCM + 审计 | ADR-009 | 明文永不出 API 层（解 PRD Q11） |
| 图表 | 自绘 SVG（不引图表库） | ADR-010 | 环形图/柱状图/横向条形图 |
| 网络 | 本机联调；生产 Nginx 三域分流 | ADR-011 | 后台内网化（解 PRD Q12） |
| 缓存 | v1 不引 Redis | ADR-013 | 触发条件已记录 |

| 依赖 | 说明 |
|---|---|

## 五、数据库实施

### 5.1 设计公约（以《03-数据库设计文档》为准）

| 约定 | 规则 | 理由 |
|---|---|---|
| 命名 | `snake_case`，表名复数、列名单数 | PostgreSQL 惯例 |
| 主键 | `BIGINT GENERATED ALWAYS AS IDENTITY`；对外用 `slug`/`code` | 不暴露数据规模，SEO 链接稳定 |
| 时间戳 | `timestamptz`（UTC） | 跨时区一致 |
| 软删除 | `deleted_at timestamptz NULL`，查询默认过滤 | 可追溯恢复，防误删 |
| 枚举 | VARCHAR + CHECK 约束（不用 PG ENUM） | 在线加值不锁表 |
| 金额 | `NUMERIC(12,2)`（单位元） | 避免浮点误差 |
| 标签 | JSONB + GIN 索引（style_tags / house_type_tags） | 案例多条件筛选一条 SQL |
| 字符集 | UTF8 | 中文检索稳定 |

| 环节 | 措施 |
|---|---|

| 迁移 | 原型 JSON 搬迁时即加密（一次到位，不留明文过渡态） |

## 六、接口实施

### 6.1 通用约定

| 项 | 约定 |
|---|---|
| 统一响应 | `{"code":0,"message":"ok","data":...}`；成功 code=0，业务异常 code≠0 |
| 分页 | 请求 `page`（从 1 起）+ `pageSize`（默认 10、上限 100）；响应 `{items,total,page,pageSize}`；**不带分页参数返回完整数组** |
| HTTP 状态 | 2xx / 400 / 401 / 403 / 404 / 409 / 429 / 5xx |
| 限流 | 公开留言 10 次/分/IP；后台 60 次/分/账号（429 + Retry-After） |
| 时间/金额 | ISO8601 UTC；金额数字（元），展示层格式化 |
| 字段校验 | 失败返回 400 + code=3xxx + 具体字段错误文案 |
| CORS | 白名单 origins；退役 file:// JSONP 回退 |

### 6.2 公开接口（13 个，无需鉴权）

| Method | Path | 说明 |
|---|---|---|
| GET | /api/v1/home | 首页聚合（精选案例×3 + 上架套餐 + 新闻预览 + 关于摘要） |

## 九、安全与合规

| 项 | 措施 | 依据 |
|---|---|---|
| 密码 | argon2id；旧 sha256 惰性重哈希 | ADR-006 |
| 令牌 | access 2h + refresh 8h 落库可撤销；连续 5 次失败锁定 15min | ADR-005 |
| 敏感信息 | 身份证 AES-256-GCM 落库 + 脱敏 + 解密审计 | ADR-009（解 PRD Q11） |
| 注入/XSS | SQLAlchemy 参数化；富文本白名单清洗；输出转义 | 技术文档 §12.4 |
| 上传 | MIME 嗅探 + ≤10MB + 类型白名单 + 路径穿越防护 | ADR-007 |
| 限流 | 留言 10 次/分/IP；后台 60 次/分/账号 | 技术文档 §6.1 |
| 合规（PIPL） | 留言最小化收集（姓名+手机号）、表单明示用途、身份证加密+审计 | PRD §10 |

**威胁模型要点**：库泄露→密码/身份证均为不可用密文；盗号/越权→JWT 短时效+可撤销+失败锁定+内网隔离双重防线；内部窥探身份证→「默认不可见，查询留痕」；注入/XSS→参数化+白名单；上传恶意文件→MIME 嗅探+白名单；刷表/暴破→限流+锁定。
