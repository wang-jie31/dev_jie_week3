## 三、S-33 revalidate 回调（ADR-001 验收硬项）

### 3.1 实现

| 侧 | 文件 | 内容 |
|---|---|---|
| 前端 | `app/api/revalidate/route.ts`（新建） | POST，校验 `x-revalidate-token`（缺失 401），tag 白名单（cases/packages/news/careers/team/site），非法 400，合法调 `revalidateTag(tag)` |
| 前端 | `lib/api.ts` | `get()` 支持 `next:{revalidate, tags}`；所有内容接口补 tags（home 聚合 cases+packages+news+site）—— ISR 秒级缓存 + 标签式即时失效双轨 |
| 后端 | `core/revalidate.py`（新建） | `revalidate(tag)`：POST `${NEXT_REVALIDATE_URL}/api/revalidate`，失败仅告警**不回滚业务**（§3.5） |
| 后端 | `core/config.py` | 追加 `NEXT_REVALIDATE_URL` / `NEXT_REVALIDATE_TOKEN` |
| 后端 | `routers/admin.py` | cases/packages/news/careers/team 全部写端点（create/update/status/delete/visibility）`db.commit()` 后调 `revalidate(对应tag)` |
| 后端 | `services/org.py` | `SiteConfigService.update_admin` commit 后 `revalidate("site")` |
| 环境 | `.env` + `apps/frontend/.env.local` | `NEXT_REVALIDATE_URL` / `NEXT_REVALIDATE_TOKEN` / `NEXT_PUBLIC_SITE_URL` |

### 3.2 验收实测（端到端真实链路）

```
1) POST /api/revalidate 无 token        → 401 {"code":4010}  ✅
2) POST /api/revalidate 带 token+合法tag → 200 {"code":0,"message":"revalidated: cases"}  ✅
3) POST /api/revalidate 带 token+非法tag → 400 {"code":3001,"message":"invalid tag: hack"}  ✅
4) 端到端：admin 登录 → PUT 改案例标题追加 [S8] → 0.5s 内 GET /cases 与 /cases/[slug]
   前台均显示新标题（不等 60s ISR 间隔）→ 还原后前台同步恢复 ✅
   ★ 后台写入 → 前台即时可见（ADR-001 验收硬项达成）
```

## 四、S-34 安全加固

### 4.1 实现

| 项 | 实现 |
|---|---|
| 登录失败限流 | `core/login_rate.py`：内存滑动窗口，每 IP ≥5 次失败/分 → 429 + `Retry-After`（§6.1，v1 不引 Redis）；`routers/auth.py` login 前置检查，失败（2001/2003）计数、成功清空 |
| 安全响应头 | `core/middleware.py` 新增 `SecurityHeadersMiddleware`，main.py 最外层注册：CSP（default-src 'self' + 宽松 script/style 内联 + img/connect 允许 API）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`、`Permissions-Policy`（camera/mic/geo 全关） |
| HSTS | 交生产部署 Nginx server 层（§12.5 明确，开发态不强制 HTTPS） |
| 密钥环境变量化 | `.env` 追加 `NEXT_REVALIDATE_TOKEN` / `NEXT_PUBLIC_SITE_URL`；`apps/frontend/.env.local` 落地；config.py 敏感值默认仅开发兜底、生产用 env 覆盖；代码无硬编码密钥 |

### 4.2 验收实测

```
1) 连续 5 次错误密码登录        → 每次 2001 账号密码错误  ✅
2) 第 6 次错误密码登录          → HTTP 429 {"code":5004,"message":"操作过于频繁，请稍后再试"}  ✅
3) 限流窗口内正确密码登录        → 仍 429（防爆破）  ✅
4) Retry-After 响应头           → retry-after: 32（按最早失败自动计算剩余等待）  ✅
5) health 响应头                → nosniff / DENY / strict-origin-when-cross-origin / Permissions-Policy / CSP 全齐  ✅
```
